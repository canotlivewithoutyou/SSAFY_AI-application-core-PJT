### NF3005 응답시간

측정값은 실행 로그의 `request.completed.duration_ms`(서버가 요청을 받아 응답을 만들기까지)입니다. 브라우저 렌더링과 네트워크 왕복은 포함하지 않습니다.

정상 추천 4회: **중앙값 약 5.8초(5,847ms), 최소 5.6초, 최대 6.2초**

판단 기준 (SLO)
- **대표 요청(정상 추천)의 p95 처리 시간 10초 이내**, 그리고 **처리 중 상태 표시 필수**입니다.
- p95는 요청 100건 중 95건이 이 시간 안에 끝난다는 뜻입니다. 평균은 느린 요청 몇 건에 끌려가서 체감을 잘 못 보여 주므로, 백분위수를 씁니다.
- 10초는 사용자가 기다리면서 집중을 유지할 수 있는 한계로 알려진 값입니다(Nielsen의 응답시간 한계 0.1초 / 1초 / 10초). 1초를 넘는 처리라 화면에 "처리 중" 표시를 두고, 완료 후 실제 실행 단계를 보여 줍니다.
- p95를 의미 있게 내려면 표본이 20회 이상 필요합니다. 백분위수는 nearest-rank 방식(정렬 후 ⌈0.95 × n⌉번째 값)으로 계산합니다.

판정
- **현재: 충족 (잠정).** 표본 4회의 최댓값 6.2초가 기준 10초보다 3.8초 낮고, 처리 중 표시를 E2E 1단계에서 확인했습니다. 다만 4회로는 p95를 확정할 수 없습니다.
- **확정 방법:** `backend/scripts/measure_response_time.bat`을 실행합니다(새 세션으로 정상 추천 20회, 약 2~3분). 결과는 `docs/evidence/perf-response-time.json`에 저장되며, 이 절을 그 값으로 갱신합니다.
- **시간 구성:** LLM 분석이 약 2.1초(약 36%), 외부 Tool 10회가 약 3.2초입니다. 판단·재계획·응답 생성은 단계마다 5ms 안팎입니다. 가장 느린 Tool은 주변 후보 조회(약 1.1초)입니다.
- **개선 여지:** 같은 세션 재요청은 캐시로 2.2초까지 줄었습니다. 후보별 상세·경로 조회를 병렬로 하면 Tool 시간을 더 줄일 수 있지만, 이번 범위에서는 하지 않았습니다.
- **한계:** 표본이 4회이고, 같은 출발지·시간대로만 측정했습니다.
