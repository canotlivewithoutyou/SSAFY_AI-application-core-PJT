> 상태: 디자인 방향 확정  
> 기준일: 2026-11-19

## 2. 브랜드 원칙

- 서비스명은 항상 **열려있DOC**으로 표기한다.
- 핵심 문구는 **“지금 열려 있는 곳보다, 도착할 때도 열려 있는 곳”**이다.
- 브랜드 이미지는 **밤길에 켜진 작은 안내등**이다.
- 귀여움과 전문성의 비율은 약 **30:70**으로 유지한다.
- 의료 정보를 다루는 서비스답게 차분하고 믿음직하되, 차갑거나 위압적으로 보이지 않게 한다.
- 홍보용 랜딩 페이지가 아니라 실제 조건 입력·탐색·추천·저장이 중심인 서비스형 웹앱으로 설계한다.

## 3. 컬러 토큰

| 토큰 | 값 | 용도 |
|---|---:|---|
| Night Navy | `#18233A` | 제목, 본문, 헤더, 신뢰감 |
| Warm Ivory | `#FFF8EC` | 기본 배경 |
| Guide Mint | `#23B69A` | 주요 버튼, 선택 상태, 경로 |
| Glow Lime | `#D7F27D` | 도착 가능, 로고·도키의 안내등 |
| Warning Amber | `#FFB45C` | 마감 임박, 일정 겹침 |
| Alert Coral | `#F46F63` | 경로 실패, 운영시간 확인 필요 |

색상만으로 상태를 구분하지 않는다. 아이콘, 상태명, 짧은 설명을 함께 제공한다.

## 4. 로고 규칙

- 심볼은 지도 핀 외곽과 불이 켜진 열린 문으로 구성한다.
- 밝은 배경에서는 네이비 심볼·워드마크와 민트 `DOC`을 사용한다.
- 어두운 배경에서는 아이보리 심볼·워드마크와 라임 `DOC`을 사용한다.
- `DOC`의 `O` 상태등은 **O의 우상단 외곽, 약 1시 30분~2시 방향**에 걸쳐 배치한다. O 내부 중앙에 놓지 않는다.
- 상태등은 작고 밝은 Glow Lime이며, 과하지 않은 번짐만 허용한다.
- 로고 비율, 자간, 심볼과 워드마크 간격을 화면마다 임의로 변경하지 않는다.

## 5. 타이포그래피와 숫자

- 기본 글꼴은 Pretendard 또는 SUIT 계열의 한글 산세리프를 사용한다.
- 둥글지만 유아적으로 보이지 않는 굵기와 형태를 선택한다.
- 제목은 Night Navy와 굵은 웨이트로 명확한 계층을 만든다.
- 본문은 충분한 행간과 명도 대비를 확보한다.
- 예상 도착 시각, 운영 종료 시각, 주행시간에는 굵은 웨이트와 tabular numerals를 사용한다.
- 권장 범위:
  - 데스크톱 핵심 제목: `44~52px`
  - 모바일 핵심 제목: `28~32px`
  - 본문: `16~18px`
  - 필드 라벨·보조 문구: `14~16px`
  - 중요 시간: `32~56px`

## 6. 형태와 깊이

- 모서리 반경은 기본적으로 `12~16px` 범위만 사용한다.
- 화면 구획은 그림자보다 여백, 정렬, 얇은 선, 배경색 차이로 만든다.
- 뉴모피즘 계열의 부드러운 깊이는 활성 입력창, 선택된 세그먼트, 주요 CTA에만 제한적으로 사용한다.
- 전체 화면을 둥근 카드로 쪼개지 않는다.
- 배지와 필 형태는 꼭 필요한 짧은 상태 표현에만 사용한다.

## 7. 레이아웃

### 데스크톱

- 기준 폭은 `1440px`이다.
- 헤더 높이는 약 `72px`이며 Night Navy 배경을 사용한다.
- 본문은 왼쪽 입력 영역 `40%`, 오른쪽 탐색·추천 영역 `60%`를 기본으로 한다.
- 두 영역은 큰 카드가 아니라 여백과 얇은 구분선으로 나눈다.
- 검색 전 우측에는 가짜 추천 결과를 표시하지 않는다. 출발지와 최대 이동 범위 등 검색 준비 정보만 보여준다.

### 모바일

- 기준 폭은 `390px`이다.
- 콘텐츠 순서는 **입력 → 탐색 상태 → 추천 결과 → 저장 버튼**이다.
- 주요 버튼의 최소 터치 높이는 `48px` 이상으로 한다.
- 도키는 데스크톱보다 작게 줄이며 정보와 버튼을 우선한다.
- 주요 저장 버튼은 결과 확인 후 즉시 찾을 수 있는 위치에 둔다.

## 8. 공통 컴포넌트

### 헤더

- 왼쪽에는 공식 로고, 오른쪽에는 `방문 계획`과 작은 API 연결 상태만 둔다.
- API 연결 상태를 큰 카드나 개발자용 패널로 표시하지 않는다.

### 입력 폼

- 필수 항목은 출발지, 출발 시각, 병원/약국, 최대 이동시간이다.
- 폼 전체를 하나의 큰 둥근 카드에 가두지 않는다.
- 라벨, 아이콘, 값의 우선순위를 명확하게 유지한다.
- 주요 CTA는 **“열린 곳 찾기”**이다.

### 탐색 상태

다음 단계를 작고 명료하게 보여준다.

`출발지 확인 → 주변 후보 조회 → 운영시간 확인 → 자동차 경로 계산 → 추천 완료`

재탐색 시 기술 로그 대신 사람이 이해할 수 있는 문장을 사용한다.

> 첫 후보는 경로를 확인할 수 없어 다음 후보를 살펴보고 있어요.

### 추천 결과

- 기관명, 유형, 주소, 예상 주행시간, 예상 도착 시각, 운영 종료 시각, 선택 근거를 우선한다.
- 도착 예상과 운영 종료를 나란히 비교할 수 있는 시간축을 제공한다.
- 주요 버튼은 **“방문 계획 저장”**, 보조 버튼은 **“다른 후보 보기”**이다.
- 추천 근거는 짧고 자연스러운 문장으로 표시한다.

> 이동시간 상한 이내이며 공개 운영 종료 전에 도착할 것으로 예상돼요.

### 저장한 방문 계획

- 날짜별 일정으로 기관명, 출발 시각, 도착 예상 시각, 소요시간을 표시한다.
- 상세 보기, 수정, 삭제를 제공한다.
- 시간이 겹쳐도 삭제를 강요하지 않으며 Warning Amber 안내로만 알린다.

## 9. 상태 표현

| 상태 | 컬러 | 표현 |
|---|---|---|
| 도착 가능 | Guide Mint / Glow Lime | 체크 아이콘 + 상태명 + 근거 문장 |
| 마감 임박 | Warning Amber | 경고 아이콘 + 남은 시간 |
| 운영시간 확인 필요 | Alert Coral | 정보·주의 아이콘 + 방문 전 확인 문장 |

상태는 작은 배지 하나로 끝내지 않고, 필요한 경우 얇은 색상선과 한 문장 설명을 함께 사용한다.

## 10. 도키 사용 규칙

- 도키는 화면의 주인공이 아니라 사용자를 안내하는 보조 요소다.
- 전체 화면에서 차지하는 비율은 최대 `20%`, 일반 화면에서는 약 `10~15%`를 권장한다.
- 한 화면에 한 번만 사용한다.
- 기본 화면: 길을 안내하는 포즈
- 탐색 중: 작은 조명을 들고 살펴보는 포즈
- 추천 성공: 안도하며 손을 흔드는 포즈
- 계획 저장: 일정 카드를 품에 안은 포즈
- 콘텐츠, 버튼, 지도, 시간 정보를 가리지 않는다.
- 새로운 포즈를 임의로 재해석하기보다 공식 스프라이트의 비율과 재질을 유지한다.

## 11. 안전 안내

화면 하단에 다음 문구를 읽을 수 있는 크기로 제공한다.

> 공개 운영시간과 예상 이동시간을 바탕으로 한 방문 안내입니다. 실제 운영 및 접수 여부는 방문 전 기관에 확인해 주세요. 이 서비스는 전문가의 의료 상담을 대신하지 않습니다.

## 12. 피해야 할 표현

- 과도한 그림자, 둥근 카드, 필 배지
- 네온 사이버펑크 분위기
- 의사·환자 스톡 사진
- 적십자와 혼동되는 빨간 십자
- 청진기, 알약, 하트비트 같은 의료 로고 클리셰
- 가격표, 후기, 구독 유도, 쇼핑몰형 상품 카드
- 한 화면에서 반복되는 도키
